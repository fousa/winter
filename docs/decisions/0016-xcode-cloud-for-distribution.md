# 0016 — Xcode Cloud builds the releases

- **Status**: accepted
- **Date**: 2026-10-23
- **Amends**: [0011](0011-no-continuous-integration.md)

## Context
[ADR 0011](0011-no-continuous-integration.md) ruled out CI: no workflow files,
no checks on push or pull requests. Getting a build onto the club's iPad still
needs an archive, signing and an upload to TestFlight, and the project owner
wants Xcode Cloud to do that rather than a laptop.

Xcode Cloud clones the repository and looks for the project and its shared
scheme. `Winter.xcodeproj` is generated by XcodeGen and is not in git, so Xcode
warns that the scheme "may only exist locally".

## Decision
Xcode Cloud archives and distributes the app. Its workflows live in App Store
Connect, not in the repository; the repository only carries
`ci_scripts/ci_post_clone.sh`, which Xcode Cloud runs after cloning. The script
installs XcodeGen with Homebrew and runs `xcodegen generate`, exactly what a
contributor does after a clone, so the project stays out of git and
`project.yml` stays the only source.

The bundle identifier and the team are personal, so they are not committed
(ADR 0008). The script writes `Config/Local.xcconfig` from two environment
variables set on the workflow: `WINTER_BUNDLE_ID_PREFIX` and
`WINTER_DEVELOPMENT_TEAM`.

ADR 0011 otherwise stands: nothing runs on pull requests or on every push, and
tests are still run locally before merging. Whether a workflow also runs the
tests is the maintainer's choice in App Store Connect.

## Consequences
- Xcode's workflow editor keeps warning that the scheme may only exist locally.
  The warning is expected: the scheme exists once the post-clone script has run.
- Every cloud build installs XcodeGen first, which adds about a minute.
- A fork that wants its own cloud builds sets the same two variables on its own
  workflow; nothing in the repository names a team or a bundle identifier.

## Alternatives considered
- **Commit `Winter.xcodeproj`**: removes the warning, but puts a generated file
  in git that has to be regenerated and committed with every change to
  `project.yml`, and drifts when it is not.
- **Archive and upload from a laptop**: no Xcode Cloud at all, but every
  release depends on one machine.
